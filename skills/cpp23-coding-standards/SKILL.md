# C++23 工程编码规范

把本 skill 用作“需要工程判断的规则集”，不要把条件性建议机械地改写成强制要求。

## 确定规则优先级

按以下顺序解决冲突：

1. 用户明确要求、项目 `AGENTS.md` 及项目文档；
2. 项目支持的编译器、标准库、平台、异常/RTTI 策略和 ABI 约束；
3. 项目本地静态检查与格式化配置；
4. 本 skill 的通用默认建议。

保持现有公开 API 和行为兼容，除非任务明确要求破坏性变更。不要仅为采用新特性而重写已清晰、正确的代码。

## 解释规范等级

| 等级 | 含义 | 审查方式 |
| --- | --- | --- |
| **必须 / 禁止** | 涉及正确性、未定义行为、资源泄漏、数据竞争或明确契约 | 作为缺陷指出并要求修复 |
| **应 / 不应** | 在通常条件下更安全或更清晰的默认选择 | 结合适用条件提出修改建议 |
| **可 / 可以考虑** | 取决于性能、ABI、依赖或团队偏好 | 说明收益与代价，不判定为违规 |

不要把“应”升级成“必须”。允许偏离默认建议，但要能说明约束、测量结果或兼容性原因。

## 执行工作流

1. 先检查项目的 C++ 标准、工具链支持矩阵、异常/RTTI 设置、公开 ABI 和本地规范。
2. 判断问题属于正确性约束、API 契约还是风格偏好，并使用相应规范等级。
3. 从主题索引中读取与任务最相关的 1–3 个引用文件；跨主题问题再按需增加。
4. 修改代码时优先保持所有权、生命周期、错误语义、线程安全和复杂度可见。
5. 使用项目既有的构建与测试入口、静态检查和运行时检测器（sanitizer）验证；不要用未验证的“现代写法”
   替换可工作的实现。
6. 评审时说明规则、适用条件、具体风险和最小修复方案，区分缺陷与可选改进。

## 跨主题必须遵守的原则

- 禁止引入悬空引用、越界访问、违反严格别名规则的对象访问、数据竞争及其他未定义行为。
- 使用 RAII 表达资源所有权；裸指针和引用默认表示非拥有关系，并明确可空性与有效期。
- 让公开 API 显式表达所有权、失败方式、失效条件、阻塞行为和线程安全级别。
- 仅在完整契约保证异常不会传播时标记 `noexcept`；`constexpr` 与 `noexcept` 相互独立。
- 保持头文件自包含。只在确实降低耦合且不会形成脆弱声明时使用前置声明。
- 按项目支持矩阵使用 C++23 库特性。对未完整支持的特性，在集中兼容层中使用功能测试宏
  （feature-test macro）和替代实现。
- 让格式、命名和 include 排序服从项目 `.clang-format`、`.clang-tidy` 及其他本地配置。

## 常用决策入口

| 需求 | 通常选择 | 前提或例外 |
| --- | --- | --- |
| 调用期间只读字符序列 | `std::string_view` | 不保存视图，且不要求空字符结尾 |
| 调用期间访问连续元素 | `std::span<T>` | 不取得所有权，并明确源对象有效期 |
| “可能没有值”且无需原因 | `std::optional<T>` | 空值本身具有明确业务语义 |
| 可预期失败且调用方需要原因 | `std::expected<T, E>` | 项目工具链支持，错误类型具有稳定语义 |
| 违反常规执行路径的失败 | 异常 | 项目启用异常，且异常可以安全跨越当前边界 |
| 独占所有权 | 值类型或 `std::unique_ptr<T>` | 优先直接值语义；确需动态生命周期时用指针 |
| 共享所有权 | `std::shared_ptr<T>` | 只有生命周期确实共享时使用，并处理环引用 |
| 后台线程和协作取消 | `std::jthread` + `std::stop_token` | 析构可能阻塞；若承诺取消，任务应及时响应停止请求 |
| 简单独立原子状态 | `std::atomic<T>` | 多字段不变量通常仍需互斥量 |
| 编译期约束 | 标准 `concept` 或 `requires` | 约束应表达语义，不为每个模板强加无意义约束 |
| 编译期多态 | `concept`、重载或 CRTP | 若需要运行时替换，选择虚函数或类型擦除 |
| 隐藏实现或稳定 ABI | PImpl | 权衡动态分配、间接访问和实现复杂度 |
