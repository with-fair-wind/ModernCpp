# 11 · API 设计与契约

## 适用范围与核心原则

让函数签名表达调用方必须知道的语义：所有权、可空性、有效期、失败、复杂度、阻塞和线程安全。不要把关键契约藏在实现中。

## 参数选择

| 语义 | 通常形式 | 必须说明 |
| --- | --- | --- |
| 小型可复制输入值 | `T` | 单位、有效范围 |
| 仅读取现有对象 | `const T&` | 调用期间是否保存引用 |
| 修改现有对象 | `T&` | 修改范围与失败后的状态 |
| 可空观察 | `T*` | 是否可空、对象有效期 |
| 连续元素借用 | `std::span<T>` | 底层存储与失效条件 |
| 字符序列借用 | `std::string_view` | 是否保存、是否要求 `\0` |
| 接收并保存一个值 | 按值接收 `T` 后移动 | 类型移动成本与赋值策略 |
| 转移独占所有权 | `std::unique_ptr<T>` | 空指针是否有效 |
| 共享生命周期 | `std::shared_ptr<T>` | 是否真正参与所有权 |

- 应优先用返回值表达结果。只有 ABI、多个独立结果、缓冲区复用或性能测量支持时使用输出参数。
- 不要用裸指针暗示所有权转移。所有权转移必须由类型或明确命名的领域接口表达。
- 保存引用、指针、视图或回调时，**必须**在公开契约中说明保存时长和失效条件。

## 契约与结果

- 把可验证的外部输入错误作为正常错误处理；把仅供程序员遵守的前置条件作为契约或断言。**禁止**在 `assert`
  表达式中放置程序正确性所需的副作用，因为非调试构建可能移除该表达式。
- 使用强类型、`std::chrono::duration`、枚举或领域值类型表达单位和状态，避免用裸整数配合注释。
- 只在忽略返回值通常表示缺陷时添加 `[[nodiscard]]`；为不明显的原因提供诊断字符串。
- 对公开 API 记录异常、错误值、复杂度、迭代器/引用失效、阻塞行为、回调重入和线程安全级别。
- 不要通过默认参数或重载制造含糊调用。布尔参数影响行为时优先使用枚举或具名选项类型。
- 虚函数的默认实参按静态类型绑定；多态接口应避免依赖这种组合。

## 兼容性与演进

- 新增重载前检查隐式转换和模板重载是否导致既有调用二义性。
- 公共类型新增数据成员、虚函数或改变布局前检查 ABI 承诺；仅源兼容不代表二进制兼容。
- 返回引用或视图的 API 应明确哪些操作会使结果失效，避免调用方从实现细节推断。

## 审查重点

- 仅阅读声明和文档，确认调用方是否能正确使用 API；若必须阅读实现，契约通常不完整。
- 检查空值、失败、取消、超时和部分成功是否都有唯一且可组合的表示。
- 检查接口是否迫使调用方依赖具体容器、分配器、线程或平台类型。
