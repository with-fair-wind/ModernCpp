# 10 · 特殊成员、移动与值类别

## 适用范围与核心原则

优先零之则：把资源交给 RAII 成员，让编译器生成正确的特殊成员。只有类型直接管理资源或需要改变复制语义时才显式声明。

## 特殊成员与资源类型

- 应优先遵循零之则。成员含 `std::unique_ptr` 时，复制操作通常会被隐式删除；移动操作只有在满足特殊成员函数的
  隐式声明条件时才会生成，例如用户声明析构函数可能抑制隐式移动。不要声称五个操作都一定存在。
- 直接管理资源时，**必须**明确析构、复制构造、复制赋值、移动构造和移动赋值的语义；不支持的操作应显式 `delete`。
- 仅当移动操作的完整实现保证异常不会传播时，将其标记为 `noexcept`。默认生成的移动操作是否不抛取决于基类和
  成员的对应操作。容器可以持有移动可能抛出的类型，但重分配时可能改用复制或只能提供较弱保证。
- 复制并交换（copy-and-swap）适合需要强异常保证且无需复用存储的类型；不要机械用于所有赋值运算。

## 参数传递与转发

- 当函数总要保存一份值，且类型移动成本低时，可以按值接收再移动到成员。左值会复制，右值通常仍至少发生一次移动。
- 对移动成本高或需要复用现有存储的类型，可提供 `const T&` / `T&&` 重载，或采用更合适的领域接口。
- 转发引用（forwarding reference）只在类型推导语境成立。使用 `std::forward<T>` 保留调用方值类别；
  无条件转移所有权时使用 `std::move`。
- 不要从 `const` 对象期待真正的资源转移；多数移动构造函数接受非 const 右值引用。

## 返回与成员限定

- 返回局部对象时直接 `return value;`，让复制消除或隐式移动生效。`return std::move(value);` 通常会阻止 NRVO。
- 移动后对象仍然有效，但值通常未指定。可以析构、赋值，并可调用其前置条件仍满足的操作；不要依赖未承诺的具体状态。
- 使用引用限定符（ref-qualifier）或 C++23 显式对象形参区分左值、右值及 const 对象的成员行为，避免重复实现。
- 使用 `decltype(auto)` 返回引用时应特别检查括号规则和被返回对象的生命周期；不要返回局部变量引用。

```cpp
struct Builder
{
    auto build() const& -> std::string { return data; }
    auto build() && -> std::string { return std::move(data); }

    std::string data;
};
```

## 审查重点

- 检查用户声明的析构函数或复制操作是否意外抑制隐式移动。
- 检查移动后的对象是否被读取、是否仍满足后续操作前置条件。
- 检查转发构造函数是否抢占复制构造、产生悬空引用或扩大重载集合。
