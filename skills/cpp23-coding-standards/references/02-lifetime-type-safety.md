# 02 · 生命周期与类型安全

## 适用范围与核心原则

让无效状态难以表达，并让借用关系短于被借用对象。任何转换都不得绕过对象生命周期、对齐或严格别名规则。

## 生命周期与借用

- **必须**保证引用、指针、迭代器、lambda 捕获和视图在使用期间指向仍然存活且未失效的对象。
- `std::string_view` 和 `std::span` 始终非拥有；返回或保存它们时必须明确底层存储和失效条件。
- 范围视图（range view）不一定非拥有；例如 `std::ranges::owning_view` 可以拥有源范围。仍应检查管道中各层的生命周期。
- 异步任务或延迟回调不应以引用捕获短生命周期局部变量。保存回调时必须记录捕获对象的所有权关系。
- 只有在确需手工管理对象存储期时使用 placement new、`std::construct_at`、`std::destroy_at` 或
  `std::start_lifetime_as`，并同时满足大小、对齐和生命周期要求。

## 类型表达与转换

- 应用 `std::optional<T>` 表达可缺省值，用 `std::variant<Ts...>` 表达封闭的备选集合，用 `std::any` 表达
  真正开放且需要运行时查询的值集合。
- `std::visit` 要求访问器可处理所有备选类型，但通用 lambda 可能掩盖新增分支；需要业务穷尽性时显式列出分支。
- 应先选择 `static_cast`、`dynamic_cast`、`const_cast` 或 `std::bit_cast` 中语义匹配的操作。**禁止**用 C 风格
  转换隐藏转换类别。
- 仅在多态基类确有运行时类型查询需求时使用 `dynamic_cast`。频繁向下转换通常表示接口抽象不足。
- 仅对大小相同且可平凡复制的类型使用 `std::bit_cast`，并确认目标类型允许所得位模式。
- **禁止**通过不兼容类型的指针或引用访问对象。序列化和字节检查优先使用 `std::byte`、字符类型或 `memcpy`。

## 继承与多态

- **必须**防止多态对象按值传递造成切片。通过引用、指针或值语义类型擦除传递多态对象。
- 作为多态基类使用的类型应具有 public virtual 析构函数，或具有 protected 非 virtual 析构函数以禁止经基类删除。
- 应优先组合。仅在派生类型满足可替换关系且基类契约稳定时使用 public 继承。
- 不要把混入（mixin）与虚接口混为一谈；CRTP 混入通常提供编译期组合，虚接口提供运行时替换。

## 审查重点

- 追踪每个非拥有句柄的创建、保存和失效位置。
- 检查 lambda、协程和线程是否把局部对象生命周期延长到了作用域之外。
- 检查转换前提是否包含对象实际类型、对齐、有效位模式和 RTTI 配置。
