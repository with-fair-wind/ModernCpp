# 05 · 容器、视图与 Ranges

## 适用范围与核心原则

根据访问模式、复杂度、内存布局和失效规则选择容器。Ranges 用于表达算法组合，不要求替换所有清晰循环。

## 容器与非拥有视图

- 应先根据顺序性、查找复杂度、稳定地址、连续存储和修改模式选择容器，不要默认所有序列都用 `vector`。
- 当接口在调用期间访问连续元素且不取得所有权时，应使用 `std::span<T>`；固定尺寸是契约时使用静态范围大小
  （static extent）。
- 表达多维非拥有数据时可以考虑 `std::mdspan`，并明确范围大小（extents）、布局映射（layout mapping）、
  访问器（accessor）与底层存储有效期。
- 查询关联容器中是否存在键时使用 `contains`；查找后还要访问值时使用一次 `find`，避免 `contains` 后再次查找。
- 使用 `try_emplace` 避免键已存在时构造值；使用 `insert_or_assign` 表达“存在则赋值，不存在则插入”。
  不要把 `operator[]` 用作纯查询。
- 修改关联容器键时可使用节点句柄（node handle）执行 `extract`、修改和重插，也可根据语义执行
  erase + insert；两种方案都要处理键冲突。
- 对读多写少、元素较少且连续存储有益的有序集合，可以考虑扁平关联容器 `std::flat_map` / `std::flat_set`，
  并评估插入成本和迭代器失效。

## Ranges 与惰性求值

- 应在管道能更直接表达转换、筛选或切片时使用 Ranges；状态复杂、需要提前退出或循环更清晰时保留显式循环。
- `std::ranges::to`、`std::ranges::fold_left` 等折叠算法和 C++23 范围适配器（range adaptor）仅在项目支持
  矩阵覆盖时使用；兼容逻辑应集中处理。
- 范围视图（range view）可能借用也可能拥有源范围。**必须**追踪借用范围（`borrowed_range`）、临时对象和
  每层范围适配器的生命周期。
- `views::take(n)` 将结果数量限制为最多 `n` 个，但上游范围产生这些元素的过程仍可能不终止；例如，无限源经
  永不满足的 `filter` 后再执行 `take(1)`。
- `std::generator<T>` 适合单遍惰性序列。它是协程实现的范围，不提供线程调度或并行执行。

## 失效与复杂度

- **必须**在容器修改后重新检查指针、引用和迭代器是否失效。尤其注意 `vector` 重分配、erase 和 flat container 插入。
- 不要假设 Ranges 管道自动更快。惰性组合可能增加调用层次，也可能让编译器融合操作；用基准验证热路径。
- 需要并行执行策略、数值重排语义或特定舍入行为时，不要机械地用 fold 替换传统算法。

## 审查重点

- 检查接口是否无意绑定到具体容器，或反过来隐藏了必需的容器语义。
- 检查修改操作后的迭代器、`std::span`、`std::mdspan` 和视图是否继续被使用。
- 检查复杂度声明、分配次数和范围遍历次数是否符合实际实现。
